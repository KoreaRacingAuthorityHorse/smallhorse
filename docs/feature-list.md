# TRACK:ON 기능 리스트

기준: `dev` 브랜치 (2026-11-22, 커밋 `1b07b3b`). 실제 코드에 구현된 화면과 로직에서 뽑았다.
프론트엔드는 아직 목업·localStorage를 쓴다. 경주 데이터는 DB 이미지 `trackon-db:dev`(`db/`)에 준비되어 있고, 기능별 연결은 맨 아래 "기능별 DB 테이블·원천 API" 표에 있다.

표의 **데이터** 열은 그 기능이 읽거나(R) 쓰는(W) 데이터이고, ERD의 엔티티 후보가 된다.

## 기능별 DB 테이블·원천 API

DB는 `racing` 스키마(`docs/erd.md`). "준비"는 DB에 실데이터가 들어 있다는 뜻이고, 프론트·백엔드 연결은 아직이다.

| 기능 | DB 테이블 | 원천 API | 상태 |
|---|---|---|---|
| B-1 경주 목록 | `race` (status: SCHEDULED·FINISHED) | API72_2 경주계획표, API3_1 경주개요 | 준비 |
| B-2 경주 상세 | `race`, `race_entry`, `entry_change` | API26_2 출전표, API214_1 경주성적, API9_1·API10_1 취소·기수변경 | 준비 |
| B-3 경주 조회 | `race`(주로·날씨·함수율), `race_entry`(마체중·장구), `entry_checkpoint`, `race_split`, `race_corner_order`, `race_payout` | API214_1, API299, API303, API6_1, API34_1, API189_1, API25_1 | 준비 |
| B-4 기수·조교사 | `jockey`, `trainer`(프로필·통산/1년 성적·승률), `race_entry`(최근 경기) | API12_1, API11_1, API19_1 | 준비 |
| B-5 경주마 | `horse`(혈통·도입가·성적·상금), `horse_rating_history`, `horse_treatment`, `race_entry`(장구·폐출혈·최근 경주) | API8_2, API77, API141, API24_1 | 준비 (진료는 최근 출전마 1,609두) |
| B-5 마주 정보 | `owner`(보유 두수·성적·상금) | API14_1 | 준비 |
| C-1 예정 경주 | `race`(SCHEDULED), `race_entry`(ENTERED), `entry_career_snapshot` | API72_2, API26_2, API25_1 | 준비 (출전표는 경주 2~3일 전 공개) |
| C-1·C-2 지난 경주 블라인드 | `race`, `race_entry`, `entry_career_snapshot` | API214_1, API299 | 준비 |
| C-4 취소마 제외 | `race_entry.status_code`, `entry_change` | API9_1 | 준비 |
| C-7 정산 | `race_entry`(착순·status_code), `entry_status.refundable`, `race_payout` | API214_1, API34_1 | 준비 |
| C-8 결과·다시보기 | `entry_checkpoint`, `race_split`, `race_payout`, `race_odds`(모든 조합 배당) | API214_1, API6_1, API34_1, API160_1 | 준비 (`race_odds`는 2026-10~11월) |
| E-2 용어 설명 | `glossary` | 자체 작성 | 준비 |
| E-3 학습 팁 통계 | `race_entry`, `entry_checkpoint`, `race_payout`로 계산 | - | 계산 쿼리 필요 |
| A-1·A-2, C-5·C-6, D-1~D-4, F-1 | 서비스 도메인(사용자·포인트·구매·정산) | - | 제외(로그인·정책 확정 후) |
